# Avledet

Valheim server written in modern C++. 

Low resource usage. Includes features not present in Vanilla.

Includes awesome Lua scripting and debugging, a questionable Discord integration, and other crazy ideas:

- Game replay 
  - Replays packets to a user to relive the past.
    - Not currently implemented, but I've thought of reimplementing it in a more robust way. The old method was
      to completely switch the server mode to a capture state, which would be somewhat expensive, because there
      is a writer thread, compression, disk usage, the whole 9 yards. For every client on the server.
    - The dataflow is interesting. Valheim stores everything as ZDO's, which are objects of their own accord.
    - Every ZDO update resends the entire ZDO, regardless of what updated. This *seems* expensive from a packet storage standpoint,
      because it is. However, it allows for accurate forward and backward progressing replays, for whoever should want that.
    - I dont know if this is a feature anybody wants, but when I got it working a few years ago, I think it was really cool.
- Bungee / proxy-like hubs
  - Too difficult right now, would require something to translate clientside ZDOs / IDs to server side ZDOs / IDs.
  - Basically, the client ID would continually increase as new ZDOs are created. These created ZDOs are effectively immutable,
    (I think..) because the client stores some persistent data about them until theyre destroyed. Even then, the ID remains unusable.
  - Yes, IDs are incremental. They arent randomly generated. They also makes previous unusable.
  - Some kind of ZDO ID => Nat table to keep track of the clients ever increasing ID, and whatever server instance they're currently connected to.
  - This creates huge constraints on the server, because Avledet uses a custom sized UserID / bit compression scheme to avoid an entire 32-bit
    number being utilized.
  - Cool idea but not really feasable.
- Rewriting Vanilla mods in Lua
  - Dungeon generation is native in Avledet. I havent tested it out in a while though.
  - There's a network compression mod (not sure if anyone uses it anymore), and I rewrote that once.
  - Jotunn configuration scheme.
    - Likely requires an entire rewrite now.
  - Sleep time skip
  - Other things eventually...

## Quick Start

Look in the Releases of Github. Or build it yourself.

- Run the executable `./avledet_server`
- The working folder is in `./data`
  - `lua/` - lua libraries and server scripts. Sandbox enabled by default.
  - `worlds/` - the list of server worlds, includes `.fwl` and `.db` files.
  - `admin.yml` - list of admin allowed players by hostname.
    - This is usually by each players SteamID
  - `server.yml` - the bread & butter of the server. 
    - More than 50+ configurable values.
    - You might want to delete the stock config because it contains
      a lot of unused and old values that no longer exist.
      Also contains many out-of-date values that might not represent the kind
      of server security / settings you would want out of the gate.
    - A new server.yml will be generated if its missing. If so, the new one
      will be freshly populated with modern and secure settings.
  - `*.pkg` - server resource files containing Valheim data dumps in a custom binary format.
    - These are generated by `AvlIntrinsics`, https://github.com/avledet/avlintrinsics
      - I have yet to update that user repository. Also, you see the user is called `Avledet`. 
        I am planning on moving everything avledet related to there someday.

## Building

### Linux

- IDE (VSCodium)
  - Extensions
    - `CMake Tools` - `ctrl + p` -> `ext install ms-vscode.cmake-tools`
    - `C/C++`
    - `clangd` - `ctrl + p` -> `ext install llvm-vs-code-extensions.vscode-clangd`
    - `Clang-Format` (optional)
    - `EmmyLua` (optional)
- Libraries
  - Steamworks SDK
    - Sign in & Download @ https://partner.steamgames.com/downloads/list
    - Extract somewhere (ie, `~/.local/bin/steamsdk/sdk`)
  - vcpkg
    - `git clone https://github.com/microsoft/vcpkg && cd vcpkg && ./bootstrap-vcpkg.sh -disableMetrics && realpath scripts/buildsystems/vcpkg.cmake`
    - Note the printed `vcpkg.cmake` path
  - Lua
    - Yes, I wrote an entire section specially for lua, because this was 1000% more complicated than it ever needed to be.
    - Classic Valhalla used a combination of static and mostly dynamic linking. This *worked*. When I switched to Linux, things switched
      to mostly static libraries, probably because of vcpkg changes. I stopped the Lua script development for a while after that because of migration-hell between
      Avledet <=> Valhalla, and overall lack of interest and other projects I had going on. Well, the lua library resolution I had no longer worked.
      I spent an entire day talking to chatgpp, the useless chatbot that provides you with hallucinated garbage. I ended up somehow fixing things by requiring that Lua be dynamically linked to the project. The "easiest" way I found to get a dynamic copy of Lua5.5 is via a vcpkg triplet. This actually generates a shared library
      that can be linked by Avledet. There is probably a better way, but for now, I am done.
    - `./vcpkg install lua:x64-linux-dynamic`
- Back to IDE 
  - Clone from VCS `ricosolana/avledet`
  - Prepare Kit
    - `Ctrl + Shift + P` => `scan for kits` => `enter`
    - `Ctrl + Shift + P` => `select a kit` => `enter`
      - Select `GCC 12.x...` or `GCC 13.x...` (the latest one)
  - CMake Arguments
    - Switch to `User` or `Workspace` (your preference)
    - `Ctrl + Shift + P` => `CMake: Open CMake Tools Extension Settings` => `Configure Args`
      - It's time to configure path arguments. These vary based on where you installed things,
        so edit them accordingly. The below is a realistic sample:
        - `-DCMAKE_TOOLCHAIN_FILE=/your/user/here/vcpkg/scripts/buildsystems/vcpkg.cmake`
        - `-DLUA_INCLUDE_DIR=/your/user/here/vcpkg/installed/x64-linux-dynamic/include`
        - `-DLUA_LIBRARY=/your/user/here/vcpkg/installed/x64-linux-dynamic/lib/liblua.so`
        - `-DSTEAMWORKS_SDK=/your/user/here/.local/bin/steamsdk`
        - I have prepopulated the project with the above (maybe). Look inside `./vscode/settings.json`.
