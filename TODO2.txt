- heightmap poll generation
	main polling for 0,-158

	when height map threads are = 1

	and worldgen is taking place, the heightmap thread is the bottleneck
	very huge bottleneck

	where is basically seems like the code is frozen / deadlocked during a world pregenerate

	but actually, the heightmap block polling freezes the calling thread until
	the builder becomes less congested, and able to process the desired heightmap

	an alternative would be to create a priority queue for heightmaps,

	where the more they are requested, the more priority they will have

	but, this is unnecessary

	---

	the system should try to be mindful of all neighbor zones when placing foliage

	ie, its possible that a foliage will need height data from a neighboring zone to place a 'foliage cluster'

	and, in cases where that neighbor heightmap is not generated yet, the code just freezes

	so in essence, a priority queue is kind of necessary, because a thread is frozen while waiting for the
	builder to get around to generating the neighbor heightmap



	at the core of it, frozen main thread = bad
	so we really want to get output to the user,
	and this actually would speed up generation
	because:
		either way, the builder will always be building, 
		it will just be building nodes which are needed *almost* immediately
		and, I say, "almost" immediately, because this is thread-thread communication.
		there are no direct calls, only expedited transfer via a priority queue
